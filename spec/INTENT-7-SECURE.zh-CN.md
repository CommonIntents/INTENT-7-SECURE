# INTENT-7-SECURE：双向TLS与边缘安全规范（v1.0.0-RFC-4）

## 1. 引言与设计目标
本规范定义了 **INTENT-7-SECURE** 标准，它是 **CommonIntents-144（CI-144）** 协议族中的密码学身份认证、传输层机密性与边缘网络安全标准。

INTENT-7-SECURE 专责**网络层与密码学链路防护**。为维持协议栈严格解耦：
- 它不管理帧边界、分片、基于序列号的防重放能力（上述能力全部交由 **BIND-19** 负责）
- 它不管理逻辑权限与任务授权映射（上述能力全部交由 **CAPABILITY-13** 负责）
- 它作为公网环境下的加密安全物理管道，同时定义边缘环境下的零信任本地校验与凭证注入边界

---

## 2. 公网环境：双向TLS 1.3密码学配置
所有远程连接（如 WebSocket、TCP、面向互联网的端点），INTENT-7-SECURE 强制要求遵循 RFC 8446 标准的**双向 TLS 1.3（mTLS）**。

### 2.1 密码套件与约束
为防范密码学降级攻击，实现必须禁用 TLS 1.2 及更早版本，仅允许以下密码套件：
- `TLS_AES_256_GCM_SHA384`
- `TLS_CHACHA20_POLY1305_SHA256`

### 2.2 双向证书校验（mTLS）
- 客户端与服务端必须交换并校验 X.509 v3 证书
- 自签名证书默认拒绝，仅当在 L0 基因锁中通过 SHA-256 指纹显式钉扎时才被接受
- 私有CA签发的证书，仅当CA根指纹已在 L0 基因锁中声明时才被接受
- 若证书与 L0 基因锁身份绑定，其生命周期管理（轮换、吊销）遵循 **CAPABILITY-13 密钥轮换协议**；否则遵循标准 X.509 CRL/OCSP 机制
- INTENT-7 元数据中的 `traceparent`（W3C 追踪上下文）必须与 TLS 会话ID或 TLS 导出密钥材料（EKM）绑定，防范会话劫持与连接复用攻击

## 3. 本地传输安全与对等身份校验（零开销）
当 BIND-19 绑定在本地 **Unix 域套接字（UDS，`unix://`）** 上时，运行高CPU开销的非对称加密（mTLS）属于资源浪费。

取而代之，INTENT-7-SECURE 强制采用**操作系统级对等身份校验**，以 **0 毫秒密码学开销** 实现绝对零信任安全：

### 3.1 套接字文件权限
物理 UDS 套接字文件（如 `/var/run/helix.sock`）创建后必须立即设置权限为 **`0600`**：
- 读写权限严格限定为运行进程的所有者
- 父目录必须做权限限制，防范路径穿越攻击

### 3.2 对等凭证校验（`SO_PEERCRED`）
当客户端（如 Anaphase）通过 UDS 连接本地数据库守护进程（Helix-Mind）时，服务端必须拦截套接字并执行**系统级对等凭证校验**：
- Linux 系统：通过 **`SO_PEERCRED`** 套接字选项获取连接客户端的 `ucred` 信息（UID、GID、PID）
- macOS 系统：通过 **`LOCAL_PEERCRED`** 套接字选项获取对等方凭证
- **严格 UID/GID 匹配**：服务端必须校验客户端 UID/GID 与服务端守护进程所有者一致；若检测到不匹配，必须立即断开连接并记录安全审计事件

## 4. Tuck代理与KMS隔离边界
为防止活跃大模型或沙箱化 WASM 工具泄露私密凭证，INTENT-7-SECURE 定义了严格的**零凭证隔离边界**。

### 4.1 凭证标签路由（无明文密钥体）
- Anaphase 执行循环与 Tentacle 工具沙箱内的任何组件，均不得持有、查看或解析明文 Cookie、密码
- 所有出站请求必须携带 **`X-Identity-Label`** 请求头
- **标签命名空间格式**：必须遵循 `<命名空间>/<标识>@<实例ID>` 结构
  - `<命名空间>`：凭证提供方作用域（如 `weibo`、`github`、`openai`）
  - `<标识>`：命名空间内的具体凭证标识
  - `<实例ID>`：（可选）Anaphase 实例唯一ID，避免会话冲突
  - 示例：`X-Identity-Label: weibo/session_1@anaphase_01`
- `Tuck` 在边缘侧拦截连接，解析标签后与内部硬件锁定的密钥管理服务（KMS）匹配，再将真实的 `Cookie: SUB=xxxx;` 或 `Authorization: Bearer xxxx` 注入 HTTP 请求头，随后发往公网

### 4.2 KMS 根目录隔离与标准兼容
- KMS 存储文件与解密私钥必须存放在只读、受硬件保护或严格根目录隔离的目录中，且仅归 `Tuck` 守护进程所有
- KMS **推荐**支持 **PKCS#11** 标准接口，或集成硬件安全模块（HSM）/可信平台模块（TPM）进行密钥存储与解密
- 即便 `Anaphase` 进程或 `Tentacle` WASM 沙箱被攻破，攻击者也只能窃取到无意义的「身份标签」，真实密钥始终安全保留在 `Tuck` 的物理边界内

## 5. 安全错误码
检测到密码学或传输层安全违规时，错误必须通过 BIND-19 错误帧（帧类型 `0x06`）向上层传递。错误帧载荷的前 2 字节承载 INTENT-7-SECURE 错误码：

| 错误码十进制 | 十六进制值 | 错误名称 | 说明 |
|:---|:---|:---|:---|
| `2000` | `0x07D0` | `MTLS_HANDSHAKE_FAILED` | 远程 TLS 1.3 握手或客户端证书校验失败 |
| `2010` | `0x07DA` | `UNTRUSTED_PEER_UID` | 本地 UDS 对等方凭证（UID/GID）与进程所有者不匹配 |
| `2020` | `0x07E4` | `KMS_KEY_INJECTION_FAILED` | Tuck 无法解密或注入标签对应的凭证 |
| `2030` | `0x07EE` | `CERTIFICATE_EXPIRED` | X.509 证书已过期 |
| `2040` | `0x07F8` | `CERTIFICATE_REVOKED` | X.509 证书已被吊销（通过 CRL/OCSP 判定） |
